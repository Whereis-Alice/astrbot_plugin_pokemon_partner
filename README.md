## 这是什么

这是一个 AstrBot 插件，包含两套互相独立、但共用同一份本地图鉴数据的能力：

1. **今日宝可梦与收藏**：每天按配置的次数和稀有度概率抽取宝可梦，收集个人图鉴、闪光个体，用重复宝可梦换星尘，再定向兑换想要的宝可梦。
2. **宝可梦资料与对战工具**：查询 1025 只宝可梦和 295 个形态的中文图鉴、特性、招式、道具、地区图鉴；计算等级能力值；查属性相性、克制关系；校验配招；模拟对战；分析队伍；查询冠军赛使用率数据。

所有图鉴、概率、对战数据都在本地。只有两项功能会联网：

- 可选的 PokéAPI 补充查询（默认开启，可在配置中关闭）；
- 宝可梦卡片缺少本地立绘时，从 PokéAPI 官方图源下载一次并缓存（默认开启，可关闭）。

关闭这两项后，插件完全离线可用。

> 本项目是独立实现，插件标识符、数据目录、指令与卡片样式均与上游 `ca1e/astrbot_plugin_pokedex` 及 `Whereis-Alice/astrbot_plugin_kirby_catalog` 分离，不会与它们共用配置或数据。

## 快速开始

### 环境要求

- AstrBot `>=4.16,<5`
- Python 依赖：`Pillow`、`aiohttp`（见 `requirements.txt`）
- 中文系统字体（Windows 自带微软雅黑；Linux 建议安装 `fonts-noto-cjk`）

### 安装

在 AstrBot WebUI 的插件管理中选择「从仓库安装」，填入：

```text
https://github.com/Whereis-Alice/astrbot_plugin_pokemon_partner
```

也可以手动放入 `data/plugins/`：

```bash
cd /path/to/AstrBot/data/plugins
git clone https://github.com/Whereis-Alice/astrbot_plugin_pokemon_partner.git
python -m pip install -r astrbot_plugin_pokemon_partner/requirements.txt
```

安装后重载插件。若卡片里中文显示为方框，说明运行环境没有中文字体，安装
`fonts-noto-cjk` 后重启 AstrBot 即可。

### 立绘（可选，但强烈建议）

插件本身**不打包**宝可梦官方立绘，以避免仓库体积和版权问题。想要完整卡片效果，
请把 [pokemon-dataset-zh](https://github.com/42arch/pokemon-dataset-zh) 的
`data/images` 目录下载到服务器，并在插件配置的「宝可梦图片目录」填写该目录的绝对路径：

```text
/path/to/pokemon-dataset-zh/data/images
```

目录结构应为 `official/`、`home/` 等子目录。AstrBot 跑在 Docker 里时，先把目录挂载进
容器，再填容器内路径。

不配置也能用：开启「本地立绘缺失时使用网络官方图」后，插件会按需下载官方图并缓存到
插件数据目录；关闭后卡片使用占位图，不影响任何文字功能。图片查找顺序为：配置的本地
目录 → 插件缓存 → PokéAPI 官方立绘 / HOME 图 / 普通精灵图。

### 一键缓存全部立绘

管理员在群聊或私聊中发送：

```text
下载立绘
```

别名是 `下载全部立绘`、`缓存立绘`。插件会以 8 路并发下载当前卡池中缺失的图片，每 40 张
处理一批，并在开始、阶段性进度和完成时回报结果。任务可以重复执行：已有图片自动跳过，
中断后再次发送即可继续补齐。

缓存默认写入 AstrBot 的插件数据目录：

```text
data/plugin_data/astrbot_plugin_pokemon_partner/artwork/
```

如果配置中关闭了 `fallback_web_image`，一键下载也会拒绝执行，避免绕过网络开关。

## 玩法说明

### 今日宝可梦

```text
今日宝可梦
```

每天有固定次数（默认 3 次），每次召唤固定数量（默认 1 位）。这两个数字都可以在配置里改：

- 想一次抽 5 位，就把「每次召唤的宝可梦数量」设为 5；
- 想每天只能抽 1 次，就把「每日召唤次数」设为 1。

**每次先按稀有度权重决定档位，再在该档位里等概率选择宝可梦。** 默认概率与卡池规模：

| 稀有度 | 默认概率 | 种族值总和 | 卡池数量（默认形态） |
| --- | --- | --- | --- |
| SSR 传说 | 3% | ≥ 580 | 92 |
| SR 史诗 | 12% | 480–579 | 331 |
| R 稀有 | 30% | 400–479 | 216 |
| C 普通 | 55% | < 400 | 386 |

概率是权重归一化后的结果，不要求相加等于 100；例如 `55/30/12/3` 就是
55% / 30% / 12% / 3%。把某一档设为 0 就不再产出该档。

如果某一档的权重大于 0、但该档卡池为空（例如把阈值调到没有宝可梦的区间），
插件会剔除该档后重新归一化，`抽取概率` 展示的也是实际生效的百分比；SSR 保底
在卡池没有 SSR 时自动不启用，不会把计数一直累积到底。

首次获得的宝可梦会写入图鉴；重复宝可梦折算星尘。开启「把地区形态/超级进化等形态计入卡池」
后，卡池会从 1025 项扩到 1229 项（缺少种族值的形态行会被跳过），每项独立收藏。

### 抽卡结果卡片

每次发送 `今日宝可梦` 都会按配置固定抽取若干只，并在发送结果前先补齐本批立绘。单抽和
多抽使用不同的信息密度：

- **单抽**：大尺寸立绘、稀有度、闪光/NEW 标记、六项种族值条形图、分类、身高体重、
  特性与隐藏特性、捕获度、弱点和抗性。
- **2–4 抽**：两列立绘网格，每格保留名字、属性、稀有度、种族值总和、特性和结果标记。
- **5–10 抽**：三列紧凑网格，优先保证立绘清晰和名称可读，同时显示属性、稀有度与种族值。

如果官方图源暂时不可用，卡片会使用同尺寸占位图，抽卡结果与收藏数据仍然正常写入。

### 我的宝可梦与会话隔离

```text
我的宝可梦
我的宝可梦 2
```

`我的宝可梦 [页码]` 只显示自己在**当前群聊**获得的宝可梦，每页 24 位；私聊则按用户独立
保存。同一账号在 A 群和 B 群的收藏、星尘、今日次数与保底进度互不影响。管理台中的
「宝可梦管理」也按相同的会话标识展示，避免跨群误操作。

### 保底

- **SSR 保底**：默认连续 30 次没出 SSR，下一次必出 SSR。计数按用户单独保存，出 SSR 后清零。
- **新宝可梦保底**：默认关闭。设置成 N 后，连续 N 次抽到重复宝可梦，下一次强制未拥有。
- 两套保底互相独立，不会因为一个触发而重置另一个。

### 星尘与兑换

重复宝可梦按稀有度折算星尘（默认 C 2 / R 6 / SR 20 / SSR 80），闪光重复再乘倍率
（默认 3 倍）。星尘用于定向兑换：

```text
兑换宝可梦 皮卡丘
兑换宝可梦 皮卡丘 闪光
```

普通与闪光分开收藏，所以已经拥有普通皮卡丘时仍可兑换闪光皮卡丘。闪光兑换价格默认是
普通价格的 4 倍。

### 收集里程碑

收集数达到 10 / 30 / 60 / 100 / 200 / 400 / 600 / 800 位时，自动发放星尘；100 位起
还会增加当天的额外召唤次数。集齐全部宝可梦有一次性奖励。

### 全部指令

| 指令 | 说明 |
| --- | --- |
| `今日宝可梦` | 消耗今日次数抽取宝可梦 |
| `我的宝可梦 [页码]` | 查看自己的收藏，每页 24 位 |
| `收集资料` | 收集进度、闪光数、星尘、剩余次数、保底进度、会话排名 |
| `兑换宝可梦 <名称> [闪光]` | 用星尘定向兑换未拥有的宝可梦 |
| `收集排行` | 当前群/私聊的收集排行 |
| `抽取概率` | 概率、卡池规模与规则说明卡 |
| `图鉴帮助` | 指令总览 |
| `重置今日宝可梦` | 管理员重置自己的今日次数 |
| `增加宝可梦次数 [数量]` | 管理员给自己增加今日次数 |
| `重置本群宝可梦` | 管理员重置本群所有人的今日次数 |
| `下载立绘` | 管理员一键缓存当前卡池的全部立绘 |

`今日宝可梦` 的别名：`抽取宝可梦`、`抽宝可梦`。

其它常用别名：`图鉴菜单` / `帮助菜单`、`抽取规则` / `抽卡概率`、`我的图鉴` /
`图鉴收藏`、`图鉴资料`、`换取宝可梦`、`图鉴排行`。

除图鉴查询主指令 `宝可梦 <名称>` 外，本插件的其他指令都不以 `宝可梦` 开头，避免被主指令
的前缀匹配截获。旧版 `宝可梦兑换`、`宝可梦排行`、`宝可梦资料` 等写法已迁移，请使用上表
中的新指令。

### 图鉴与对战

| 指令 | 说明 |
| --- | --- |
| `宝可梦 <编号/名称>` | 图鉴卡片（含冠军赛名次） |
| `宝可梦 <名称> 招式表 [等级]` | 可学招式与推荐配招 |
| `宝可梦 <名称> 能力值 [等级 个体 性格]` | 官方公式计算等级能力值 |
| `特性 <名称>` / `招式 <名称>` / `道具 <名称>` | 数据查询 |
| `性格 [名称]` | 25 种性格修正与口味速查 |
| `相性 <属性1> [属性2]` | 防守方向相性 |
| `相性 打 <属性>` | 进攻方向相性 |
| `克制 <宝可梦>` | 推荐克制它的候选 |
| `克制 <A> <B>` | 两只宝可梦多维度对比 |
| `对战 <A> <B> [等级] [详细] [种子=123]` | 配招效果、逐回合战报与可复现对局 |
| `队伍分析 <名称...>` | 共同弱点、全队抗性与属性覆盖 |
| `筛选 速度>100 特攻>=120` | 按种族值筛选 |
| `宝冠军 [关键词]` | 冠军赛数据一站式查询 |
| `许愿星 <性格> [个体] [TID SID]` | 许愿星基拉祈种子筛选 |

群聊中 `@机器人` 直接提问时，模型可以自动调用图鉴工具（需要模型支持 function calling）。
工具采用「一个动作一个函数」的原子设计，方便模型组合，例如先分析队伍，再逐只查询配置。

### 看懂对战与完整复盘

```text
对战 皮卡丘 喷火龙 50
对战 皮卡丘 喷火龙 50 详细 种子=123
```

开场显示双方的四招、属性/物理或特殊分类、威力、命中、PP、图鉴说明与**实际模拟效果**。
自动配招来自对应等级的升级招、招式学习器和遗传招，避免将 Z 招式、极巨招式或未实现的
特殊伤害公式当普通高威力招。没有本地学习表时会明确标为演示配招。

对局支持先制度与速度、能力等级（±6）、本系加成、属性倍率、暴击、PP/挣扎、麻痹、灼伤、
中毒、递增剧毒、睡眠/冰冻，以及已登记招式的追加状态、畏缩、回复、吸血、反伤、守住、
蓄力和攻击后休息。每回合写明招式、剩余 PP、命中/失败、伤害与 HP，并记录状态和能力变化。
双方倒下或达到回合上限时判平局。默认能力为 31 个体、0 努力、中性性格。

普通特性只实现飘浮、避雷针、蓄电、引火、储水的属性免疫部分；吸收回血、能力提升、天气、
场地、道具、换人等规则尚未覆盖。蓄力期间仍可被命中；羽栖不会暂时移除飞行属性；
未实现的图鉴效果会在配招中标注。战报用于资料理解和可复现演示，不等同于官方实战计算器。

长对局默认展示前六回合与最后两回合；追加 `详细` 保留全部回合，长消息会按完整行拆分发送。
复制战报中的 `种子=...` 可重复同一场对局。LLM 工具 `simulate_battle` 同样支持 `seed` 和 `detailed`。

## Dashboard 管理台

安装并重载插件后，打开 AstrBot Dashboard 的插件页面，选择「宝可梦图鉴管理台」。页面不
另开端口，后端 API 统一挂在 `/astrbot_plugin_pokemon_partner/` 下，并继承 Dashboard 的登录
鉴权；只有已登录的管理台用户才能访问。

管理台提供五个工作区：

| 工作区 | 用途 |
| --- | --- |
| 数据概览 | 查看训练家数、图鉴收录、闪光数、累计抽取、今日活跃、卡池构成与数据健康状态 |
| 宝可梦图鉴 | 按名称、属性、世代、稀有度筛选 1025 只默认形态及 295 个特殊形态；点击后从悬浮抽屉查看立绘、六项种族值、特性、相性、图鉴描述与招式 |
| 宝可梦管理 | 按群聊/私聊会话查看成员收藏，调整星尘、今日次数和保底，导出会话 JSON 备份，重置或删除指定数据 |
| 概率与规则 | 同时查看配置权重与剔除空卡池后的实际概率、种族值阈值、经济表与各项上限 |
| 设置 | 在线修改核心参数；服务端先校验，重载失败时回滚旧配置，不会写入不可用状态 |

界面采用精灵球红、纸白和深墨色的图鉴研究站主题，支持浅色、深色与跟随系统。图鉴列表读取
本地/缓存缩略图，不为整页批量联网下载；可切换立绘网格与紧凑列表，按 `/` 快速聚焦搜索。
选中宝可梦后从右侧打开大立绘详情，并按配置补齐缺失图片。抽屉可通过关闭按钮、点击遮罩或 `Esc` 收起；移动端会占据几乎
整个屏幕，正文独立滚动。管理台与群聊指令共用同一个 `GachaStore` 文件锁和写入逻辑，因此
不会绕过会话隔离，也不会产生两份互相覆盖的数据。

「导出会话收藏」包含结构版本、导出时间和该会话的收藏记录，不包含插件配置或密钥。
导出仅提供备份文件，暂不提供自动导入。存档写入失败时回滚本次内存与随机状态；损坏立绘
会被跳过，并在允许联网时重新缓存。

## 配置说明

### 抽卡与概率

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `gacha_enabled` | `true` | 关闭后不加载抽卡系统，其他功能不受影响 |
| `draws_per_command` | `1` | 每次召唤固定抽取几位（1–10） |
| `daily_draw_limit` | `3` | 每日基础次数（0–100） |
| `draw_cooldown_seconds` | `3.0` | 两次召唤的最短间隔 |
| `rarity_weights` | `C55/R30/SR12/SSR3` | 四档稀有权重，按比例归一化 |
| `rare_min_bst` | `400` | R 档最低种族值总和 |
| `super_rare_min_bst` | `480` | SR 档最低种族值总和 |
| `ultra_rare_min_bst` | `580` | SSR 档最低种族值总和 |
| `ssr_pity_after` | `30` | 连续多少次未出 SSR 后必出；0 关闭 |
| `new_pity_after` | `0` | 连续多少次重复后必出新；0 关闭 |
| `allow_duplicate_draw` | `true` | 关闭后优先抽未拥有的宝可梦 |
| `include_alternate_forms` | `false` | 是否把形态计入卡池（开启后 1229 项） |
| `shiny_chance_percent` | `1.5` | 闪光概率 |
| `duplicate_dust` | `2/6/20/80` | 重复宝可梦折算星尘 |
| `spark_costs` | `20/60/150/400` | 星尘兑换价格 |
| `shiny_dust_multiplier` | `3.0` | 闪光重复的星尘倍率 |
| `shiny_spark_multiplier` | `4.0` | 闪光兑换的价格倍率 |

三个稀有度阈值必须严格递增，否则插件会记录错误并停用宝可梦系统，图鉴功能仍然可用。

## 数据目录

插件使用独立标识符，数据默认位于：

```text
data/plugin_data/astrbot_plugin_pokemon_partner/
├── gacha/
│   ├── state.json          # 各会话的收藏、星尘、次数、保底
│   └── state.json.bak      # 上一次成功写入的备份
├── artwork/                # 自动下载的立绘缓存
└── champions.db            # 可选：冠军赛数据库
```

`state.json` 使用临时文件 + `os.replace` 原子写入，并保留一份 `.bak`。写入失败不会破坏
旧文件。备份或迁移时请复制整个 `astrbot_plugin_pokemon_partner` 数据目录。

如果 `state.json` 损坏，插件会自动从 `.bak` 恢复（可能丢失最后一次写入），并把损坏
文件另存为 `state.corrupt-<时间>.json`；主文件与备份都无法读取时会停止写入并提示管理员
检查，而不是用空数据覆盖。恢复后不会再把损坏文件复制成新的备份。

写入时会额外加一把跨进程文件锁（POSIX `flock` / Windows `msvcrt`），并在落盘前合并
磁盘上的较新数据。因此插件热重载瞬间新旧实例并存、或同一份数据被两个进程打开时，
不会互相覆盖已收集的宝可梦。

群聊按群隔离，私聊按用户隔离：同一个人在 A 群和 B 群的收藏互不影响。更换群号或清空
数据目录都会重置对应收藏，操作前请备份。群聊优先使用平台群 ID；若适配器没有提供
`group_id`，会继续读取原始事件群标识或 AstrBot 会话 ID，避免误归入私聊数据。

### 冠军赛数据

冠军赛查询依赖 `champions.db`，插件运行时只读，不联网。抓取脚本需要额外的 Playwright：

```bash
pip install -r requirements-scraper.txt
playwright install chromium
python champions_fetch.py                 # 最新赛季，单打+双打
python champions_fetch.py --top 50        # 多抓配置明细
python champions_fetch.py --season M-6    # 指定历史赛季
```

脚本默认写入 `data/plugin_data/astrbot_plugin_pokemon_partner/champions.db`，与插件读取
路径一致。站点改版导致选择器失效时，可用 `--headed` 查看实际渲染并调整
`champions_fetch.py` 顶部的 `JS_*` 常量。

## 常见问题

**Q：抽卡没有图片，只有文字。**
先检查是否安装了 Pillow、系统是否有中文字体，以及 AstrBot 日志里是否有「渲染失败」。
图片下载失败时会使用占位图；整张卡片渲染失败才会回退文字，不影响抽卡结果。

**Q：卡片上的宝可梦没有立绘。**
没配置 `images_dir`，且网络图下载失败或已关闭 `fallback_web_image`。配置本地图片目录
即可彻底离线。

**Q：概率和我想的不一样。**
权重是归一化后的比例，不是百分比总和必须为 100。可在 `抽取概率` 或管理台「概率与规则」
里看到实际百分比
和每档池内数量。

**Q：为什么抽到的都是同一只？**
默认 `allow_duplicate_draw=true`，重复是正常结果并会折算星尘。想更快集齐可以关闭它，
或设置 `new_pity_after`。

**Q：和 `astrbot_plugin_pokedex` 能同时装吗？**
插件标识、数据目录、注册类名与收藏指令都不同，可以在 AstrBot 中共存；但两个插件都可能
注册通用指令 `宝可梦 <名称>`。如果需要同时安装，请在 Dashboard 的指令管理中只保留其中
一个的图鉴查询指令，避免前缀冲突。

**Q：数据会随插件更新丢失吗？**
不会。更新只替换插件代码，不改 `data/plugin_data/astrbot_plugin_pokemon_partner/`。
卸载插件时是否删除数据取决于 AstrBot 的卸载选项，重要数据请先备份。
