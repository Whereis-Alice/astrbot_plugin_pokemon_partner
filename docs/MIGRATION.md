# 数据备份与服务器迁移

[返回首页](../README.md) · [配置与管理](ADMIN.md) · [QQ 官方 Bot](QQ_OFFICIAL.md)

收藏、闪光、星尘、每日次数、保底进度、对战胜负与已完成的对战记录，可以一起导出并迁移到另一台服务器。仅更换服务器、继续使用相同的平台和机器人身份时，通常无需填写 ID 映射。

## 用管理台搬家

1. 在原服务器打开「宝可梦图鉴管理台」→「宝可梦管理」，选择要迁移的会话，点击「导出迁移备份」。选择全部会话可导出所有数据。
2. 在新服务器安装并启用本插件，打开同一工作区，展开「数据迁移与恢复」，选择导出的 JSON 文件。
3. 保持「保留已有会话」，点击「预览备份」，检查会话数、成员数、普通与闪光数量、星尘、对战记录，以及将导入或跳过的会话。
4. 确认预览正确后点击「确认导入」。完成后查看收藏、星尘和战绩；同一个群里发送 `我的宝可梦`、`收集资料`、`对战记录`，也能核对结果。

预览不会修改收藏数据。实际导入会重新校验，并先备份新服务器的当前存档，再原子写入。导出和导入与聊天功能共用文件锁；原服务器可以在线导出。正式切换时应停止旧服务器继续抽卡，避免导出后产生的新数据遗漏在迁移包之外。

### 已有数据怎么处理

| 方式 | 行为 |
| --- | --- |
| 保留已有会话 `keep_existing` | 新服务器已有的整个群聊或私聊会话都会跳过；只导入不存在的会话。重复导入不会重复增加宝可梦或星尘。 |
| 替换备份中的对应会话 `replace` | 用备份替换其中的对应会话；新服务器其他会话保留。适合恢复备份，或在新 Bot 登记成员后导入旧收藏。 |

这里按**整个会话**处理冲突，不会把同一群的两份收藏自动相加。需要替换时，先另行导出新服务器的数据，并检查预览中的冲突会话。

## 从 OneBot 换到 QQ 官方 Bot

QQ 数字账号、群号与官方 Bot 的 `openid` 是不同的标识。即使是同一个人、同一个 QQ 群，也必须明确填写对应关系；插件不会按昵称或训练家编号猜测旧数据归属。更换官方 Bot 应用时，也应重新核对标识。

1. 在原服务器的管理台查看旧会话 ID 和成员 ID，导出对应会话的迁移备份。
2. 让成员在新官方 Bot 的目标群里发送 `训练家编号`。名片会显示该会话的训练家编号、管理员迁移用的会话 ID 和成员 ID。管理员核实本人对应关系后记录下来。
3. 在「更换平台：群聊与成员映射」中填写两个 JSON 对象。对象左侧是旧 ID，右侧是新 ID，全部使用字符串。
4. 先备份新服务器已登记的数据，再选择「替换备份中的对应会话」，预览并导入。登记已创建目标会话，选择「保留已有会话」会跳过它。

会话映射示例：

```json
{
  "group:123456789": "group:qq_official:实际群openid"
}
```

成员映射示例：

```json
{
  "10001": "实际成员openid-A",
  "10002": "实际成员openid-B"
}
```

请把示例值替换成管理台与训练家名片显示的真实 ID。`T-XXXXXXXX` 是当前会话内用于挑战的公开训练家编号，不是这里要填的成员 ID。

私聊换平台时也应填写完整会话映射，例如 `private:10001` → `private:qq_official:实际用户openid`。插件只会自动跟随成员映射更新同一种平台格式的私聊 ID；不会替你把 OneBot 私聊转换成官方 Bot 私聊。

没有映射的 ID 会原样保留，因此未登记成员的旧收藏不会被删除，但新官方身份暂时无法使用它。若不同群的成员对应关系不同，可以分别导出、分别填写映射和导入。多个旧会话或同一会话的多个旧成员映射到一个新 ID，会被拒绝，避免误合并他人的数据。

## 备份里有什么

| 内容 | 处理方式 |
| --- | --- |
| 普通、闪光及特殊形态收藏 | 原数量与编号完整保留；目标卡池暂未启用的形态也保留原数据 |
| 星尘、每日次数、额外次数、保底 | 按原日期和原数值保留，迁移不会重置当天次数 |
| 对战胜负与已完成记录 | 保留；成员映射同步更新战绩和对战双方 |
| 待接收、进行中的短时挑战 | 清除，迁移后重新发起 |
| 卡面、概率等非敏感配置 | 放在备份中供核对，不会自动覆盖新服务器的配置 |
| Bot 凭据、API key、服务器路径、图片缓存、冠军赛数据库 | 不包含；凭据在新 AstrBot 重新配置，本地图片与数据库可单独准备 |

迁移包为不超过 32 MB 的 JSON，带格式版本和 SHA-256 校验和。文件损坏、校验失败或数据结构无效时会拒绝导入。旧管理台导出的会话 JSON 和原始 `state.json` 也可导入；它们没有迁移包校验和，预览会提示这一点。

备份包含用户标识和收藏资料，应存放在自己的受控位置，不要提交到公开仓库。

## 自动备份与恢复

实际导入前的备份保存在：

```text
data/plugin_data/astrbot_plugin_pokemon_partner/gacha/migration_backups/
    before-import-时间-随机编号.json
```

管理台完成提示会给出路径。提交失败时，旧存档与内存状态会回滚，导入前备份仍保留。没有会话需要导入时不写数据，也不重复生成备份。

要撤回一次已成功的导入，先导出当前数据，删除本次导入后新增的会话，再预览并以「替换」方式导入对应的 `before-import-…json`，恢复原来已有的会话。仅导入该备份不会自动删除它原本没有记录的新会话。

## 命令行迁移

在插件目录中使用 AstrBot 的 Python 环境执行。`--state-dir` 必须指向**实际含有 `state.json` 的 `gacha` 目录**；Docker 部署使用容器内路径。下面的路径都需要替换成自己的目录。

原服务器导出：

```bash
python scripts/migrate_data.py \
  --state-dir /AstrBot/data/plugin_data/astrbot_plugin_pokemon_partner/gacha \
  export --output /backups/pokemon-backup.json
```

新服务器先预览，再导入：

```bash
python scripts/migrate_data.py \
  --state-dir /new/AstrBot/data/plugin_data/astrbot_plugin_pokemon_partner/gacha \
  preview --input /backups/pokemon-backup.json

python scripts/migrate_data.py \
  --state-dir /new/AstrBot/data/plugin_data/astrbot_plugin_pokemon_partner/gacha \
  import --input /backups/pokemon-backup.json
```

跨平台迁移可将上述映射分别保存成 `scopes.json`、`users.json`，在 `preview` 和 `import` 后使用相同参数：

```text
--mode replace --scope-map /backups/scopes.json --user-map /backups/users.json
```

如需一并导出非敏感配置，在子命令 `export` 前加 `--config-file /path/to/plugin-config.json`。导出命令拒绝覆盖已有输出文件，也不能把输出路径设为正在使用的 `state.json` 或 `.bak`。

如果选择直接复制整个插件数据目录，请先停止源、目标两端的插件，再复制 `gacha`、所需图片缓存和可选数据库；不要在持续写入时独立复制 `state.json` 与 `.bak`。正常搬家优先用上面的快照导出流程。
